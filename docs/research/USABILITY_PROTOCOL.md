# Usability Evaluation Protocol — CyberCase

สถานะ: protocol สำหรับการทดสอบที่เสนอ ปรับตาม workflow ปัจจุบันเมื่อ 2026-09-22 ยังไม่มีผลการทดสอบผู้ใช้

แบบประเมินความง่ายในการใช้งานของ CyberCase Intelligence Framework
สำหรับผู้เข้าร่วม 5–10 คน ใช้เวลาต่อคนประมาณ 30–40 นาที

---

## 1. สิ่งที่ต้องการรู้

ผู้ใช้เข้าใจและทำงานให้จบได้ด้วยตัวเองหรือไม่ ใน 3 เรื่อง

1. เพิ่มข้อมูลคดีเข้าระบบ (ข้อความและไฟล์)
2. อ่านผลวิเคราะห์และย้อนกลับไปยัง source ที่ระบบอ้างถึง
3. เห็นว่าระบบบอกว่ายังขาดข้อมูลอะไร แล้วตอบคำถามเพื่อวิเคราะห์ต่อได้

ไม่ได้วัดความถูกต้องของผลวิเคราะห์หรือความเหมาะสมทางกฎหมาย — นั่นเป็นคนละการทดลอง
MITRE/technical context เป็นส่วนเสริมที่ไม่จำเป็นต่อ protocol หลักนี้

---

## 2. ผู้เข้าร่วม

- 5–10 คน
- มีพื้นฐานด้านการอ่านเอกสารคดี การวิเคราะห์ข้อมูล หรือ IT พอสมควร ตามประชากรที่กำหนดใน thesis
- **ไม่เคยใช้ระบบนี้มาก่อน** ถ้าเคยเห็นตอนพัฒนา ให้ตัดออก
- บันทึกไว้ต่อคน: สาขา/ตำแหน่ง, ปีประสบการณ์ที่เกี่ยวข้อง, ความคุ้นเคยกับระบบลักษณะเดียวกัน

- [ ] ระบบรันได้ทั้ง frontend และ backend
- [ ] เปิด `rag_service` เฉพาะเมื่อ protocol ต้องการทดสอบ technical appendix แยกต่างหาก

- [ ] ไฟล์หลักฐานตัวอย่าง 1 ไฟล์ (PDF หรือภาพ) วางไว้บนเดสก์ท็อป
- [ ] ข้อความคดีตัวอย่าง (ภาคผนวก ก) พิมพ์หรือเปิดไว้ให้คัดลอกได้
- [ ] ใบยินยอม (ภาคผนวก ค) เซ็นแล้ว
- [ ] นาฬิกาจับเวลา และแบบบันทึก (ภาคผนวก ข)

**บทพูดเปิด** — อ่านให้ผู้เข้าร่วมฟังตามนี้

> เรากำลังทดสอบระบบ ไม่ได้ทดสอบคุณ ถ้าตรงไหนงงหรือหาไม่เจอ นั่นคือข้อมูลที่เราต้องการพอดี
> รบกวนพูดออกมาดัง ๆ ว่ากำลังคิดอะไรอยู่ กำลังมองหาอะไร
> ผมจะไม่ช่วยจนกว่าจะติดจริง ๆ เกิน 2 นาที และคุณหยุดเมื่อไหร่ก็ได้

## 4. งานที่ให้ทำ

ให้โจทย์ทีละข้อ ห้ามบอกวิธี จับเวลาตั้งแต่อ่านโจทย์จบจนผู้เข้าร่วมบอกว่าเสร็จ

### งานที่ 1 — เปิดคดีใหม่และกรอกเรื่องราว
> "สมมติคุณได้รับแจ้งเหตุนี้มา ให้บันทึกเข้าระบบ"
> (ยื่นข้อความคดีตัวอย่างให้)

สำเร็จเมื่อ: คดีถูกสร้าง และเรื่องราวถูกบันทึกเป็น source แล้ว

### งานที่ 2 — แนบไฟล์หลักฐาน
> "มีไฟล์หลักฐานเพิ่มมาอีกหนึ่งไฟล์ อยู่บนเดสก์ท็อป ให้แนบเข้าคดีเดียวกัน"

สำเร็จเมื่อ: ไฟล์ขึ้นในรายการ และข้อความที่สกัดได้แสดงผล

### งานที่ 3 — สั่งวิเคราะห์และอ่านผล
> "ให้ระบบวิเคราะห์คดีนี้ แล้วสรุปประเด็นสำคัญ ใครเกี่ยวข้อง เหตุการณ์ตามลำดับ และข้อมูลใดที่ระบบอ้างกลับไปยัง source ได้"

สำเร็จเมื่อ: ผู้เข้าร่วมค้นพบสรุป ประเด็นสำคัญ และ source ที่ระบบอ้างถึงได้ โดยไม่ต้องบอกตำแหน่งล่วงหน้า

### งานที่ 4 — หาข้อมูลที่ยังขาด แล้วเติมกลับ
> "ระบบบอกว่ายังขาดข้อมูลอะไรบ้าง เลือกมาหนึ่งเรื่อง แล้วเติมข้อมูลนั้นเข้าไป จากนั้นให้วิเคราะห์ใหม่"

สำเร็จเมื่อ: ผู้เข้าร่วมหาประเด็นที่ค้างคาเจอ ตอบคำถามใน Chat และไปต่อจนระบบวิเคราะห์รอบถัดไปได้

*(งานนี้คือหัวใจ — ถ้าคนหาไม่เจอว่าระบบบอกอะไรค้างไว้ แปลว่าการแสดงผลตรงนั้นล้มเหลว)*

### งานที่ 5 — สร้างรายงาน
> "สร้างรายงานของคดีนี้ แล้วดาวน์โหลดเป็น PDF"

สำเร็จเมื่อ: ได้ไฟล์ PDF

## 5. สิ่งที่เก็บ

**ต่องาน** (ลงในภาคผนวก ข)

| เก็บอะไร | วิธีบันทึก |
|---|---|
| ผลลัพธ์ | สำเร็จเอง / สำเร็จโดยต้องใบ้ / ไม่สำเร็จ |
| เวลา | วินาที |
| จุดที่หลงทาง | นับจำนวนครั้งที่คลิกผิดที่หรือย้อนกลับ |
| คำพูด | จดคำพูดตรง ๆ โดยเฉพาะตอนงงหรือตอนเข้าใจ |

**หลังจบทุกงาน** — แบบสอบถาม SUS 10 ข้อ (ภาคผนวก ง)

**คำถามปิดท้าย 3 ข้อ** ถามปากเปล่า จดคำตอบ

1. ตรงไหนของระบบที่สับสนที่สุด
2. ถ้าแก้ได้อย่างเดียว จะแก้อะไร
3. คุณเชื่อผลวิเคราะห์ที่ระบบให้มากน้อยแค่ไหน เพราะอะไร

---

## 6. วิธีคิดคะแนน SUS

ข้อคี่ (1, 3, 5, 7, 9): คะแนนที่ได้ − 1
ข้อคู่ (2, 4, 6, 8, 10): 5 − คะแนนที่ได้
บวกทั้งหมด แล้วคูณ 2.5 → ได้ 0–100

เกณฑ์อ้างอิงที่ใช้กันทั่วไป (Bangor et al., 2009; Sauro, 2011)

| คะแนน | ความหมาย |
|---|---|
| ≥ 80.3 | ดีมาก (A) |
| 68–80.2 | ดีกว่าค่าเฉลี่ย (B–C) |
| 68 | ค่าเฉลี่ยของระบบทั่วไป |
| 51–67 | ต่ำกว่าค่าเฉลี่ย (D) |
| < 51 | ต้องแก้ (F) |

รายงานผลเป็น **ค่าเฉลี่ย ± ส่วนเบี่ยงเบนมาตรฐาน** พร้อมอัตราความสำเร็จของแต่ละงาน
ที่ n = 5–10 อย่าอ้างนัยสำคัญทางสถิติ ให้รายงานเป็นผลเชิงพรรณนาและปัญหาที่พบ

## ภาคผนวก ก — ข้อความคดีตัวอย่าง

> เมื่อเช้าวันจันทร์ พนักงานแผนกบัญชีแจ้งว่าเปิดไฟล์ในโฟลเดอร์ที่ใช้ร่วมกันไม่ได้
> ชื่อไฟล์ถูกเปลี่ยนไปหมด และมีไฟล์ข้อความวางอยู่ในโฟลเดอร์เรียกร้องให้ติดต่อกลับทางอีเมล
> ฝ่ายไอทีตรวจสอบพบว่ามีการล็อกอินเข้าบัญชีผู้ดูแลระบบจากเครื่องในสำนักงานเมื่อคืนวันอาทิตย์
> เวลาประมาณตีสอง ซึ่งไม่มีใครอยู่ในออฟฟิศ

*(ปรับข้อความได้ แต่ต้องใช้ชุดเดียวกันกับผู้เข้าร่วมทุกคน)*
