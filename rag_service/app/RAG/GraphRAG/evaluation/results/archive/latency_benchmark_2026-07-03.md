## สรุปเหตุการณ์

เว็บไซต์ลงทะเบียนผู้ป่วยของโรงพยาบาลถูกโจมตี ผู้ต้องสงสัยใช้เทคนิคที่เรียกว่า SQL Injection เพื่อ突破เข้าไปในเซิร์ฟเวอร์ฐานข้อมูลผ่านช่องค้นหาผู้ป่วย หลังจากเข้าไปแล้ว ผู้ต้องสงสัยติดตั้งสคริปต์ที่ซ่อนอยู่ (เรียกว่า web shell) บนเซิร์ฟเวอร์เพื่อรักษาการควบคุมระยะไกล จากนั้นผู้ต้องสงสัยสแกนเครือข่ายภายในของโรงพยาบาลเพื่อค้นหาคอมพิวเตอร์เครื่องอื่น ใช้ข้อมูลประจำตัวผู้ดูแลระบบที่ถูกขโมยเพื่อเข้าถึงเซิร์ฟเวอร์บันทึกทางการแพทย์ผ่าน Remote Desktop ปล่อยแพร่ ransomware เพื่อเข้ารหัสไฟล์ทั้งหมด ลบสำเนาสำรอง และปล่อยข้อความเรียกค่าไถ่ที่ขอ 5 Bitcoin

## ลำดับการโจมตี

1. ผู้ต้องสงสัยใช้ประโยชน์จากจุดอ่อนในช่องค้นหาผู้ป่วยโดยการฉีดโค้ด SQL ที่เป็นอันตรายเพื่อเข้าไปในเซิร์ฟเวอร์ฐานข้อมูล (SQL Injection — T1190)

2. ผู้ต้องสงสัยอัปโหลด web shell (สคริปต์ที่ซ่อนอยู่) ไปยังเซิร์ฟเวอร์เว็บเพื่อสร้างวิธีการควบคุมระยะไกลและการดำเนินการคำสั่งที่ยั่งยืน (Web Shell — T1505.003)

3. ผู้ต้องสงสัยสแกนเครือข่ายภายในของโรงพยาบาลเพื่อระบุคอมพิวเตอร์และระบบอื่นที่อาจเป็นเป้าหมาย (Scanning IP Blocks — T1595.001)

4. ผู้ต้องสงสัยใช้ข้อมูลประจำตัวผู้ดูแลระบบที่ถูกขโมยเพื่อเข้าสู่ระบบเซิร์ฟเวอร์บันทึกทางการแพทย์โดยใช้ Remote Desktop Protocol (RDP) ซึ่งเป็นฟีเจอร์ที่อนุญาตให้เข้าถึงอินเทอร์เฟซกราฟิกของคอมพิวเตอร์จากระยะไกล (Remote Desktop Protocol — T1021.001)

5. ผู้ต้องสงสัยปล่อยแพร่ ransomware ที่เข้ารหัสไฟล์ทั้งหมดบนระบบที่ได้รับผลกระทบ ทำให้ผู้ใช้ที่ถูกต้องตามกฎหมายไม่สามารถเข้าถึงได้ (Ransomware — T1486)

6. ผู้ต้องสงสัยลบสำเนาเงา (shadow copy) ทั้งหมด ซึ่งเป็นสำเนาสำรองอัตโนมัติที่เก็บไว้โดยระบบ โดยใช้คำสั่งระบบเพื่อป้องกันการกู้คืนไฟล์ที่เข้ารหัส (Inhibit System Recovery — T1490)

7. ผู้ต้องสงสัยปล่อยข้อความเรียกค่าไถ่ที่ขอการชำระเงินเป็น Bitcoin เพื่อแลกกับการถอดรหัสไฟล์ (Financial Theft — T1657)

- **T1486** Ransomware — ผู้ต้องสงสัยปล่อยแพร่มัลแวร์ที่เข้ารหัสไฟล์ทั้งหมดบนระบบที่ได้รับผลกระทบ ทำให้ไม่สามารถใช้งานได้โดยไม่มีคีย์ถอดรหัส

- **T1657** Financial Theft — ผู้ต้องสงสัยขอการชำระเงินเป็น Bitcoin เพื่อแลกกับการถอดรหัสไฟล์ โดยพยายามบังคับให้โรงพยาบาลจ่ายเงินค่าไถ่

- **--fast**: แม่นยำใกล้เคียง agent ที่ความเร็ว 3×: ได้ T1204.002 และ T1046 ถูก (ที่ agent พลาด) และเก็บ C2 (T1071) เข้ามาด้วย — คุณภาพต่อเวลาถือว่า "คุ้มสุด" สำหรับเคสที่ข้อมูลครบ จุดอ่อนคือ Q1 แมป "ใช้ domain admin เข้าถึง DB server" เป็น **T1570 (Lateral Tool Transfer)** ซึ่งคลาดเคลื่อน (ควรเป็น T1021/T1078)
- **--ultrafast**: เร็วสุดแต่ **ID ผิด/หลอนบ่อยสุด** — Q1: T1059.001 (PowerShell) หลอนขึ้นมาเองทั้งที่ไม่มีในเคส, ใช้ T1190 กับ "backdoor เชื่อม C2" (ผิด), แมป Mimikatz เป็น T1110/T1555 (ผิด ควร T1003.001); Q2: T1505.**004** (Web Shell จริงคือ .003) และ **T1076** (RDP รหัสเก่าที่ถูก deprecated แล้ว — ปัจจุบันคือ T1021.001) เหมาะเป็น triage เร็ว ไม่ควรยกไปใช้ในสำนวนจริง
- **ข้อสังเกตสำคัญ**: "รอบเยอะ ≠ แม่นเสมอ" — Q2 ตัว fast แม่นกว่า agent (fast ได้ T1046 ถูก / agent ได้ T1595.001 ผิด) เพราะ agent ป้อน context จาก sub-query จำนวนมาก อาจดึง node เพี้ยนเข้ามาปน

### 3. Follow-up — จุดชี้ขาดของเคสข้อมูลไม่พอ (Q3)

นี่คือความต่าง "เชิงพฤติกรรม" ไม่ใช่แค่ความเร็ว:

- **ธรรมดา** ทำถูกทาง: decomposer คืน NONE (fix ใหม่ทำงาน — log: `no usable sub-queries … using the whole query`, ยิง retrieve แค่ 1 query ไม่เผา quota) → evaluator = **INSUFFICIENT** → หยุดถาม follow-up (12.5s) → resume ด้วยข้อเท็จจริงที่ผู้ใช้เติม → เทคนิค (T1110/T1078/T1005/T1048) อ้างอิงข้อมูลจริง
- **--fast** หยุดถามไม่ได้ (ออกแบบให้ไม่ pause) → **แต่งเรื่องทั้งเส้น**: โยงถึงกลุ่ม **VOID MANTICORE (G1055)** + T1682/T1586 ทั้งที่ไม่มีรายละเอียดเลย — อันตรายสุดในบริบทสำนวนคดีเพราะอ่านแล้วดูมีหลักฐาน
- **--ultrafast** หยุดถามไม่ได้เช่นกัน แต่ตอบสั้น เดา 2 เทคนิค (T1586/T1682) พร้อมคำ hedge "อาจ" — สร้างเรื่องน้อยกว่า fast เพราะถูก cap ให้สั้น

**นัยเชิงระบบ**: fast/ultrafast ไม่มีวาล์ว INSUFFICIENT — input ข้อมูลไม่พอจะได้คำตอบมั่วโดยไม่เตือน สำหรับ use case อัยการควรบังคับโหมดธรรมดาเมื่อ input ยังเป็นสำนวนไม่ครบ

### 4. บั๊กรองที่เจอระหว่างเทส (นอกเหนือ decomposer ที่แก้แล้ว)

- **QueryMerger ปั่น rewritten query เป็น markdown**: ตอน resume Q3 query ที่ 2 ที่ป้อนเข้า retrieval คือ `**Brute Force T1110 Credential Access, Valid Accounts T1078 Lateral Movement, Exfil…` — มี `**` + เลข technique/ป้าย tactic ปนเข้าไปในคำค้น (บายพาส decomposer จึงไม่โดน guard ที่เพิ่งเพิ่ม) ควรให้ merger เขียน rewrite เป็นวลีบรรยายเหตุการณ์ล้วน ไม่ใส่เลข ID/markdown เพราะ BGE-M3 จะไป match ป้ายพวกนี้กับ metadata แทนตัวเทคนิคจริง
- **evaluator SUFFICIENT ทั้งที่ retrieval อ่อน** (Q3 หลัง resume): reranker score แบน ~0.50 (Cobalt Strike / VOID MANTICORE / Firmware Modification — ไม่เกี่ยวเคส) แต่ evaluator ผ่านเพราะดู incident_facts ที่ผู้ใช้เติม ไม่ได้ดูคุณภาพ retrieval — เรื่องเดิมที่ค้าง (evaluator วัด topical relevance ไม่ใช่ answerability)
- **อักษรจีนหลุดในขั้น translation** (agent Q2: "เพื่อ突破เข้าไป") — Haiku แทรกอักษรจีนเป็นครั้งคราวตอนแปลไทย ควรมี post-check กรอง CJK ที่ไม่ใช่ไทย/อังกฤษ

### สรุปเชิงคำแนะนำ

| ต้องการ | ใช้โหมด |
|---|---|

| ดูภาพรวมเร็ว ข้อมูลครบอยู่แล้ว | **--fast** (คุ้มสุด: 3.3× เร็ว คุณภาพใกล้ agent) |
