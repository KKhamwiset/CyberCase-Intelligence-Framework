# Frozen evaluation protocol — 2026-10-06

This evaluates the current uncommitted grounding refactor at main `1d3c997a`. It does not change production semantics, thresholds, prompts, model selection, storage, or RAG. The production file hashes and pre-existing Git status are preserved in `tmp/projection-validation/baseline.json`.

## Current boundary

`reading_from` → `bound_claims` resolves Evidence Unit IDs to original source spans, then calls `ProjectionValidator` on every Party, Timeline and Impact. Evidence resolution is structural; source-to-claim semantic support is not checked on the direct path. `item_support` describes supporting-citation availability, independently of the semantic verdict.

Projection eligibility requires nonempty known claim IDs, supporting citations on every linked claim, and `reported` epistemic status on every linked claim. The hypothesis includes the complete party name/role, timeline time/event, or impact description; premise concatenates only linked claim texts. NLI must select entailment and assign ≥0.5 entailment probability for `supported`. Neutral, contradiction and low entailment produce `not_supported`. Missing/unknown/unbound/qualified claims, >512 input tokens or unavailable pinned weights produce `unassessed`. No truncation or semantic repair is introduced.

`judgement_request` / `reading_payload` omit every projection except `supported`. All claims, their evidence content and epistemic statuses, answered follow-up text, and optional external technical context still reach Judgement. Claims can therefore leak claim-level errors, and Judgement can infer a projection-only error again. Neither summary claim-link binding nor the `validated` trace marker establishes summary entailment. The joined trace retains every projection; reports display rejected/unassessed projections with verdict notes. Reports are affected directly through these notes and indirectly through Judgement's summary/gaps. They do not remove every rejected fact from the document.

Existing structural counters cover evidence references, resolution/invalidity, direct/recovered claims and claims lacking evidence. Per-projection verdict/reason/model/entailment is retained. There is no production projection-count, NLI-call or latency counter; this harness wraps the exact validator and scorer in its own process.

## Data and gold

- Twelve controlled cases: six English and six independently authored Thai equivalents, four clean claims each, two documents, 15 projections each. Each type has one explicit positive and four plausible controlled negatives. Perturbations change name/role/legal role/borrowed role; time/event/borrowed event/causality; amount/asset/severity/borrowed impact. Original evidence and linked claims are unchanged.
- Six saved system outputs: first three sorted English no-grammar Reading outputs from `raw_main_20261001_021428` and first three Thai clean Reading outputs from `raw_20261001_223057`. All original projections are retained, avoiding prediction-selected examples. Original bound claim text and epistemic status are preserved. Historical canonical citations are remapped once to Evidence Units by exact original-source containment; failed remaps stay unbound. This is data preparation, not an exact-quote comparison experiment.
- Gold tests explicit support from linked claims, not truth in a source or the real world. Controlled positives/negatives are specified by construction. Saved-output annotations and rationales are authored using an explicit-support rule before any model inference. The labels are independent of NLI predictions but AI-assisted; no second human adjudication or inter-rater reliability claim is made. Ambiguous metonymy, relative anchors and modality stay separate from binary quality metrics.
- Inputs, annotations, source paths/hashes and propagation targets are frozen in `data/` before inference. Runners assert hashes. No threshold or dataset adjustment is permitted after observing predictions; corrections require a new documented benchmark version.

## Conditions and metrics

No validation admits everything. Claim-link-only requires nonempty known IDs, with no semantic check. Proposed uses the exact production verdict and admits only `supported`. The optional lexical baseline is omitted to keep scope focused.

Structural diagnostics exercise valid/unknown/malformed/stale/cross-source/duplicate/empty IDs, multi-unit/multi-document/QA claims and two isolated legacy controls. Evidence resolution rate = valid nonduplicate generated ID occurrences / all generated ID occurrences. Duplicate and invalid rates include repeated occurrences, with per-claim uniqueness scope. Direct/recovered/unresolved distributions are pointer-occurrence counts; claims with no reference are counted separately. These diagnostics cannot estimate naturally occurring invalid-ID prevalence or citation entailment.

For semantic labels: assessed precision/recall/F1/accuracy exclude `unassessed`, which is neither a supported nor an unsupported prediction. Full-denominator false acceptance = unsupported rows admitted / all gold-unsupported rows; false rejection = supported rows explicitly rejected / all gold-supported rows. Supported retention = supported rows admitted / all gold-supported rows, counting both rejection and abstention as lost coverage. Assessed denominators and abstention by gold class are also saved. Ambiguous rows enter operational counts/cost, not semantic classifier scores. Results are split by type, language and origin.

Case-family percentile bootstrap uses 2,000 draws and seed 20261006, clustering bilingual equivalents and all their perturbations. These intervals describe the small constructed sample; they do not establish population performance. Downstream descriptive rates also receive Wilson intervals. Exact paired McNemar uses discordant binary outcomes and is exploratory when cases share source/context families. The [official McNemar documentation](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html) specifies the exact binomial variant; [proportion interval documentation](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.proportion_confint.html) documents Wilson intervals.

## Paired downstream replay

Eighteen projection-only targets are selected before inference: Party wrong role, Timeline wrong time and Impact wrong amount in controlled contexts 1–3, in both languages. Each frozen Reading contains the same four grounded claims and three structured projections, with exactly one injected unsupported projection. Two additional pairs diagnose claim-level and combined errors; they are excluded from the primary propagation denominator. No new Reading call occurs.

Both conditions use identical configured Judgement model/provider order, system prompt, grammar, decoding defaults, claim/evidence payloads, follow-up history and external context. Only structured admission differs. Baseline restores all three structured projections; proposed uses production filtering. Claim-link-only has the same payload as no validation in these fully linked cases, so an extra duplicate Judgement run is unnecessary. The current fixed prompt says projections have passed validation even in the baseline counterfactual; this is a controlled payload ablation, not an exact replay of the historical prompt. It also tells Judgement to derive facts from claims, potentially limiting baseline propagation.

No MITRE context is supplied for these general-case targets; associations must remain empty. This does not measure technical augmentation. One sampled output per case/condition is used with randomized condition order, recorded configuration and raw responses; no seed-supported determinism is asserted. Bounded execution permits at most 40 stages, production retries and a 1 USD request-token reservation cap at the configured Gemma providers' conservative recorded 0.10/0.30 USD per million input/output tokens. A model mismatch fails; no automatic provider/model fallback is added. Actual usage and retries are retained; cost estimates are not invoice claims.

Downstream annotations are authored after blinded reading of saved summary/gaps/associations, independently of NLI. Count unsupported fact propagation when an output asserts the target as case fact (including an attributed claim presented as supplied factual evidence). Negated statements or questions asking to establish the target are not fact propagation; target mentions/uncertainty are recorded separately. Each annotation needs a supporting excerpt and rationale, and is tied to output hashes. Unreviewed/failed responses remain missing, never counted as successful prevention. Source-to-claim errors are not credited to projection validation.

## Cost

Measure actual scorer `judge` calls, fit checks, cached duplicates, per-projection and per-case wall time; separate binding+validation from projection validation. Model load/checksum cost is separate. Record actual device/dtype/threads and dependency versions. The missing configured host model folder is measured independently from an explicitly selected existing pinned-cache path. The cached-model benchmark uses two CPU threads without changing deployment settings; its latency is a local controlled measurement, not service latency or GPU throughput. No downloads, training, translation service or production deployment occurs.
